2
3功能编号:F057(会话全文查询 FTS5 核心)· 联动 F009/F011(FTS 索引 = JSONL 的**派生
4副本**,原则 1)/F042(session.renamed 标题入索引)/F063(user.message_edited 级联更新
5索引)/F060(repair 索引对账:落后即整体重建)/F058(compaction 不折叠 FTS——索引独立
6于压缩)/F064(CLI `search` 子命令)。权威口径:specs/session_query.py.md(编码契约)、
7PRD-Core §5.6 F057、EVENT-SCHEMA §4.2(派生视图纪律:FTS 是日志投影,可整体丢弃
8重建)、CFG.md §3.7(storage.fts.index_batch_ms=200/query_timeout_s=5/result_limit=20)、
9ERR.md §2.3(PERS-2xx)、SECURITY.md §8.3(索引同权限 600,不进版本库)。
10
11一句话:给全会话历史建 **SQLite FTS5 派生索引**,实现"上次让它整理过某文件夹"式
12检索——索引**只做可整体重建的派生副本,永不写回、更不替代 JSONL 真源**(原则 1:
13任何一行索引可删了重放日志再建);订阅 append 事件异步攒批(200ms)增量索引,关键词/
14短语查询返回命中(带 **seq** 锚点,下游按 seq 回原会话 JSONL 取全事件);中文分词弱
15用"每字成词索引 + 查询端二元切分与连续子串补偿"(unicode61 局限如实标注);查询超时
165s 软降级返回空+告警;索引损坏/落后由 rebuild() 整体重建。
17
18实现要点(逐条兑现 spec):
191. events_fts 为 FTS5 虚表,每行从 JSONL 事件派生,行键 (session_id, seq) 唯一;
20 本模块对 JSONL 只读(rebuild 经注入 replay 源读),禁止任何"索引写回日志/日志补
21 索引"双写路径(INV-01);索引可随时 DELETE 全表重建,JSONL 一行不改。
222. on_event 订阅持久事件 → 白名单抽取文本(user.message.content / agent.message.content /
23 llm.response.content / tool.result.summary / session.renamed.new_title /
24 user.message_edited.new_content(更新 target 行)/ context.compacted.summary);
25 攒批:≥200ms(index_batch_ms,定时器)或 ≥64 条批量落库;瞬时事件(llm.chunk)永不索引。
263. query(q, limit=20, session_id?, actor?, after_ts?) —— 中文 2-gram + 英文 ≥3 字符词;
27 词长低于下限 → EVT-100 拒;整串短语补偿;按 FTS5 rank 排序截断 ≤limit;**超时软降级**
28 返回 {"hits": [], "timed_out": True} + WARNING,不抛不挂(检索属 UX 场景)。
294. 每条 Hit 带 (session_id, seq, type, ts, snippet, rank) —— seq 即 JSONL 行号锚;
30 CLI/UI 拿到 Hit 后经 session.events_between(seq, seq) 回原会话取全事件。
315. rebuild(session_id=None) 全量/单会话重建:清派生行 → 重放 JSONL → 逐事件重插
32 (与 on_event 同一白名单/抽取逻辑,INV-03);崩溃后半索引/repair 对账落后时调用。
336. detach 幂等摘除;delete_session 级联删该会话索引行;索引物理位置 ~/.pyharness/index.db
34 (WAL,权限 600,与 storage KV 分库;SQLite 串行写由进程内锁保证)。
35
36中文分词与 unicode61 局限(如实标注):
37- SQLite 默认 unicode61 分词器把连续中文当**一个 token**(只按标点/空白切分),对
38 "搜 2 字词"完全不适用——实测 SQLite 3.50 下对原文直查 '备份'/'备份*' 均 0 命中。
39- 本实现采用**索引侧每字成词**:写索引前把中文连续串逐字以空格隔开(每字一个 token,
40 英文/数字连续段保持整词 token,其余字符丢弃),FTS5 即可表达"相邻字"短语。
41- **查询端二元切分**:查询串中文段滑窗产 2-gram,每个 2-gram 转成相邻单字短语
42 ("备份" → `"备 份"`,quoted phrase = 相邻 token 序列),OR 合并保证召回;
43 **连续子串补偿**:整串(≥4 字/字符)再按同规则切成 token 短语 OR 上,收紧命中精度。
44- 局限:索引/摘要片段展示为字间带空格文本(查询结果 snippet 已做字间空格回缩美化);
45 同音/繁体不联想;2 字以上连续子串命中依赖"查询串含于原文连续字串",跨词序不命中。
46
47偏离说明(契约 = specs/session_query.py.md;本仓库既有实现约束下的取舍,均列理由):
481. **actor 冗余列 + 7 列行**:spec 建表 6 列但注"actor 过滤需冗余 actor 列"且 query
49 伪码带 actor=? —— 二者矛盾;取 spec 注的意图:建表含 actor UNINDEXED,行按 7 列
50 插入,snippet 取 content 列(索引 6,伪码的 5 是 6 列布局下的旧序号)。
512. **行键唯一性靠伴生表而非 INSERT OR IGNORE**:FTS5 无唯一约束,实测同 (session_id,
52 seq) 二次 INSERT OR IGNORE 会落两行——spec 伪码幂等语义无法靠 OR IGNORE 兑现;
53 故加伴生表 fts_rows(session_id, seq PRIMARY KEY) 在**同一事务**内做幂等闸
54 (INSERT OR IGNORE 进 fts_rows 成功才写 events_fts),对外行为与 spec 一致。
553. **rebuild 对 user.message_edited 走共享抽取路径**:spec rebuild 伪码只按 _WHITELIST
56 重插,会丢编辑(重放原 user.message 旧文,编辑事件被跳过);本实现与 on_event 共用
57 _extract(),重放遇 edited 同样 UPDATE target 行——保证 INV-03"重建与增量逐行一致"
58 及 F063"编辑后 rebuild 仍搜得到新版"。
594. **查询串不整体嵌入 MATCH**:spec 伪码把原始 q 直接引号嵌入(含引号即语法错,靠
60 OperationalError 兜空);本实现短语补偿串先经自研 tokenizer 清洗再引号化,含引号
61 查询不会破坏 MATCH 语法(OperationalError 兜底保留为双保险)。
625. **无 repo 装配面时 announce 降级**:spec announce 依赖 bus.tools.register_tool /
63 locator.mount —— 本仓库阶段无 F064 消费方与全局工具装配,announce 在 ctx 带
64 tools/registry 时注册工具并挂 ctx.session.fts,否则仅记 info(装配面缺失不阻断);
65 注册入口单独提供 register()(spill 同款形态)供后续装配。
666. **全文/单会话 rebuild 数据源注入**:spec 伪码直接调 persistence.replay;本实现经
67 attach_source(sid, store) 注入可回放源(鸭子类型:store.replay() 或
68 SessionLog.events_after(0) 均可),单测不依赖真实用户目录。

71仅作字段访问);不反向写 session/persistence。外部:sqlite3(stdlib,FTS5 ≥3.9,Python
723.11 自带)、asyncio(攒批定时/超时闸)、threading(单连接串行写)。无 LLM 依赖。

137 """会话全文查询 FTS5 派生索引(F057)。
138
139 派生纪律(原则 1):events_fts 每一行都从 JSONL 事件派生,行键 (session_id, seq)
140 唯一;对 JSONL 只读,禁止"索引写回日志/日志补索引"双写路径;索引可随时 DELETE
141 全表重建(rebuild),JSONL 一行不改——FTS 是日志投影,可整体丢弃重建(EVENT-SCHEMA
142 §4.2)。物理:SQLite WAL 单库(默认 ~/.pyharness/index.db,权限 600),进程内锁
143 串行化写与查询线程(单连接 check_same_thread=False + threading.Lock)。
144
145 订阅 append 事件异步攒批(≥64 条或 index_batch_ms 定时器)→ 批量 INSERT;
146 user.message_edited 级联更新 target 行(派生视图允许更新,真源不动);查询 5s
147 超时软降级返回 QueryResult(timed_out=True),不抛不挂;rebuild/delete_session
148 提供整体重建与级联删除。

228 # ------------------------------------------------------------ 批量落库
229 async def flush(self) -> int:
230 """把 _pending 批量落库(幂等,行键 (sid, seq) 唯一)+ _pending_edits 更新。
231
232 先取走缓冲再写(失败回填:拒新不丢旧);INSERT OR IGNORE 进伴生表 fts_rows
233 成功才写 events_fts(偏离 2:幂等语义落地);同一事务提交(WAL);返回新写入
234 行数。SQLite 写失败 → PERS-202 + 回填缓冲(repair/rebuild 可自愈,不中断
235 主流程)。进程内锁与查询线程互斥(单连接串行写)。
236 """
237 if self._db is None:
238 raise_code("PERS-202", op="fts_flush",
239 hint="索引未装载(enter 未执行或已 detach)",
240 advice="先 enter/重新装载索引")
241 rows, edits = self._pending, self._pending_edits
242 self._pending, self._pending_edits = [], [] # 先取走(失败可回填)
243 if not rows and not edits:
244 return 0
245 n = 0
246 try:
247 with self._lock:
248 with self._db: # WAL 事务(原子提交)
249 for r in rows:
250 cur = self._db.execute(
251 "INSERT OR IGNORE INTO fts_rows(session_id, seq)"
252 " VALUES(?,?)", (r[0], r[1]))
253 if cur.rowcount: # 行键首见才写 FTS 行
254 self._db.execute(
255 "INSERT INTO events_fts VALUES(?,?,?,?,?,?,?)", r)
256 n += 1
257 for sid, tseq, newc in edits: # 派生视图更新(真源不动)
258 self._db.execute(
259 "UPDATE events_fts SET content=? "
260 "WHERE session_id=? AND seq=?",
261 (_index_text(str(newc)), sid, tseq))
262 except sqlite3.Error as e:
263 self._pending = rows + self._pending # 回填:拒新不丢旧
264 self._pending_edits = edits + self._pending_edits
265 raise_code("PERS-202", op="fts_flush", n=len(rows),
266 hint=f"FTS 索引落库失败: {e}",
267 advice="运行 repair(F060) 重建索引;缓冲已回填不丢")
268 except BaseException: # 取消等:同样回填再上抛
269 self._pending = rows + self._pending
270 self._pending_edits = edits + self._pending_edits
271 raise
272 return n

274 # ------------------------------------------------------------ 对账读数
275 def max_seq(self, session_id: str) -> int:
276 """该会话在索引里已落库的最大 seq(派生视图末位,F060 落后对账用)。
277
278 只读;索引未装载 → 0(调用方据 0 判定"未索引",不算落后);与攒批 flush
279 共用连接锁,避免读数与写批交错。判据 SQL 与 ``read_max_seq`` **同源**
280 (``_MAX_SEQ_SQL``),保证"装配内读数"与"装配外读数"口径一致(CND-06)。
281 """
282 db = self._db
283 if db is None:
284 return 0
285 with self._lock:
286 try:
287 row = db.execute(_MAX_SEQ_SQL, (str(session_id),)).fetchone()
288 except sqlite3.Error as e:
289 raise_code("PERS-202", op="fts_max_seq",
290 hint=f"索引末 seq 读数失败: {e}")
291 return int(row[0] or 0) if row else 0
