多层级文档工程体系Layered Doc Engineering v1.0

把「给 AI 编码 Agent 用的工程规格」组织成 10 层有明确输入输出契约的生产线——每层解决一类信息衰减，上一层是下一层的唯一输入源，治理层反向检查全链。点击任意一层，查看这层包含哪些文档、每份是什么、干什么用。

全部文档清单

一页看全：每层的「文档 / 是什么 / 干什么用」逐条列出，不用一层层点。层内顺序即推荐阅读顺序。

层间契约

每层只做三件事：接收上游输出 → 加工成自己的产出 → 交付给下游消费方。横向层（锚定、约束）被反复引用，纵向层构成主线。

Agent 型专属文档

引擎型 / Agent 型项目才有的文档；产品型项目用专项手册替代。

按「什么时候看哪份」速查

同一份文档在不同阶段的价值不同——这张表回答「我现在该翻哪份」。

一句话概括各层分工：锚定层定规矩，需求层定目标，架构层定骨架，工程层定零件，specs 定到函数级，约束层定红线，FLC 定质量，治理层定可信度。

五道质量门禁

体量可以靠模板灌水，深度不能——深度门禁数的是「这段文字里有多少个真实决策」。

复用手册

层内可并行，层间必须串行——下游依赖上游产出。违反这条，就会出现「架构文档里的模块清单和需求里的功能对不上」。

步骤做什么关键约束
1复制模板目录到新项目模板含 10 层骨架
2第 1 层起步：先填技术约束 + 系统定位 + 参数表不可跳过，它是所有层的判据源
3自上而下逐层推进：需求 → 架构 → 工程 → 编码规格层间串行
4约束层与其他层并行（输入是第 1 层 + 各层现状）逐维度独立成册
5全部层落盘后跑门禁脚本禁止词 / 引用有效性 / 体量声明
6治理层全量扫描 → 出矛盾矩阵 → 打回对应层修复复扫直至 P0 = 0
7交付层：生成导航页 + 可浏览文档站体量与真实文件偏差 ≤5%

完整纲领（分层依据、逐层说明、反模式清单）、门禁脚本与项目模板均按需提供。
